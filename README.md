# Portfolio [![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fdillionverma%2Fportfolio)

Built with next.js, [shadcn/ui](https://ui.shadcn.com/), and [magic ui](https://magicui.design/), deployed on Vercel.

# Features

- Setup only takes a few minutes by editing the [single config file](./src/data/resume.tsx)
- Built using Next.js 14, React, Typescript, Shadcn/UI, TailwindCSS, Framer Motion, Magic UI
- Includes a blog
- Responsive for different devices
- Optimized for Next.js and Vercel

# Getting Started Locally

1. Clone this repository to your local machine:

   ```bash
   git clone https://github.com/dillionverma/portfolio
   ```

2. Move to the cloned directory

   ```bash
   cd portfolio
   ```

3. Install dependencies:

   ```bash
   pnpm install
   ```

4. Start the local Server:

   ```bash
   pnpm dev
   ```

5. Open the [Config file](./src/data/resume.tsx) and make changes

## Automated portfolio content

The project cards, featured merged PRs, and downloadable résumé are generated by
`.github/workflows/sync-portfolio.yml`. The workflow runs daily, can be started
manually, and accepts a `profile-readme-updated` repository dispatch from the
`blackdragoon26/blackdragoon26` profile repository.

Required profile-repository configuration:

- `PORTFOLIO_SYNC_TOKEN`: a fine-grained personal access token that can dispatch
  workflows to `blackdragoon26/muchBetterPortfolio`.

Portfolio-repository configuration for the OAuth-based Google Drive upload:

- `DRIVE_OAUTH_TOKEN`: the authorized-user JSON generated by
  `python scripts/setup_oauth.py`.
- `DRIVE_FOLDER_ID`: the destination folder in the authorized Google Drive.

The merged-PR filter defaults to repositories with at least 300 stars. Override
it with the portfolio repository variable `PORTFOLIO_MIN_REPO_STARS`. Generated
JSON, screenshots, the generated résumé section, and PDF are committed by the workflow so
the website remains static and requires no application backend.

### Wall of Fame metadata contract

Each numbered project in the profile README must be followed by a hidden block.
The visible sentence remains the card description; the hidden block is the
machine-readable source for links, exact stack, screenshots, and résumé fields:

```md
9. [<b>Project Name</b>](https://project.example): Visible card description.
<!-- portfolio-meta
repo: https://github.com/blackdragoon26/project-name
live: https://project.example/
stack: Go, React, PostgreSQL
screenshot: auto
screenshot.wait_seconds: 7
resume: yes
resume.objective: What problem the project solves.
resume.approach: First concrete implementation point || Second implementation point
resume.impact: A measurable or verifiable outcome.
-->
```

Rules:

- `repo` is a full GitHub repository URL, `private`, or `none`.
- `live` is an HTTPS deployment URL or `none`.
- `stack` is authoritative and comma-separated. GitHub topics are never used as
  technologies.
- `screenshot: auto` captures the visible live page during CI. When there is no
  live deployment, the workflow uses the repository social preview or a local
  generated fallback. An explicit HTTPS image URL is also accepted.
- `screenshot.wait_seconds` is optional and controls how long CI waits after the
  page loads before capturing it (maximum 240 seconds). Use a longer value for
  deployments whose Render backend needs time to wake up.
- `resume: yes` inserts that project into the existing “Key Projects / Open
  Source Contributions” section. `resume: no` keeps it on the website only.
- `resume.approach` uses `||` between bullet points.

The workflow fails with the project name and missing key when a metadata block
is incomplete, preventing silently stale cards.
